A Closer Look at Methods & Classes

Method Overloading

Polymorphism
  • Two or more methods in the same class share the same name.
  • Must differ in parameter types or number of parameters.
  • Return type alone CANNOT differentiate overloaded methods!
  • Enables compile-time (static) polymorphism.

Automatic Type Conversion

Exam Trap
  • Java searches for an exact parameter match first.
  • If missing, Java automatically widens types (e.g., int → double).
  • If you have test(double) and pass int 88, it executes test(double).
  • Java will never automatically narrow (e.g. double → int).
💡 1-Liner: Exact match wins; otherwise primitives auto-widen upward to the next compatible overloaded method without error.

Constructor Overloading

Initialization
  • Multiple constructors with different parameters in the same class.
  • Allows creating objects in various ways: default, cube (single param), or full dimensions.
  • Common pattern: Box() indicates uninitialized (e.g. -1), Box(len) for cube.

Call by Value vs Reference

High Yield
  • Primitives: Passed strictly by value. Changes inside method have no effect outside.
  • Objects: The reference is passed by value. Both caller and method point to same heap object!
  • Mutating object fields inside a method directly alters the caller's object.
💡 1-Liner: Java is 100% pass-by-value; but for objects, the "value" being copied is the memory memory reference itself!

Objects as Parameters & Returns

OOP Patterns
  • Methods can take class types: e.g., boolean equalTo(Test o).
  • Copy Constructor: Box(Box ob) creates a clone initially identical to an existing object.
  • Methods can instantiate and return new objects (e.g., Test incrByTen()).

Static Members & Blocks

Tricky
  • Static members belong to the class, shared across all instances (no per-object copy).
  • Static block: Executes strictly once when class is first loaded into memory.
  • 3 Strict Restrictions on static methods:
    1. Can only directly call other static methods.
    2. Can only directly access static data.
    3. Cannot refer to this or super!
💡 1-Liner: Static code has no "this" instance pointer because it runs before and independently of any object instantiation.

The 'final' Keyword (Fields)

Constants
  • Prevents modification; turns a variable into a constant.
  • Must be initialized in one of two places:
    • Directly at declaration: final int FILE_NEW = 1;
    • Inside a constructor (blank final).

  • transferOut(BankAccount receiver, double amt): deducts from self, adds to receiver, returns updated receiver.

Nested Classes, Inheritance, Abstract Classes & Interfaces

Nested & Inner Classes

Class Design
  • Inner Class (non-static): Has direct access to all outer class variables/methods (even private).
  • Static Nested Class: Must access outer members through an object instance.
  • Can define inner classes within any block scope (e.g. inside a method or even a for loop).

CLI Args & Varargs (...)

Syntax
  • main(String args[]): Arguments stored as string array (args[0], args[1]).
  • Varargs: void test(int... v) takes variable number of arguments (treated internally as array).

Inheritance & Constructor Order

High Yield
  • Uses extends. Java supports single inheritance only for classes.
  • Subclass cannot access private members of superclass.
  • Constructor Execution Order: Parent constructor executes first, followed by child! Java calls super() automatically.
💡 1-Liner: Base class must be fully constructed in memory before derived extensions can be safely layered onto it.

Upcasting vs Downcasting

Exam Trap
  • Upcasting (Allowed): Superclass reference can hold subclass object: Figure f = new Rectangle();
  • Downcasting (Illegal without cast/object): Dog d = new Animal(); fails with Compilation Error!
  • Why error? A pure Animal object doesn't have the specialized fields/methods required by Dog.
💡 1-Liner: Reference type determines which members are accessible at compile time; runtime object type determines which method body executes.

The 'super' Keyword (3 Uses)

Core OOP
  • 1. Access parent variables: super.x (when shadowed by child x).
  • 2. Call parent method: super.show() (when overridden in child).
  • 3. Call parent constructor: super(a, b) (must be 1st statement in child constructor).

Overriding & Dynamic Method Dispatch

Polymorphism
  • Subclass provides its own implementation with same name, params, and return type.
  • Enables Runtime Polymorphism via Dynamic Method Dispatch (DMD).
  • Cannot override: static, final, or private methods!
  • Covariant return: Subclass can return a narrower subtype (e.g. Dog instead of Animal).
  • Visibility rule: Subclass can increase visibility (protected → public), but cannot reduce it!
💡 1-Liner: DMD resolves the method call at runtime by checking the actual heap object type, not the reference type.

Abstract Classes & Rules

Abstraction
  • Class with one or more abstract methods must be declared abstract.
  • CANNOT be instantiated directly: new AbstractClass() is illegal.
  • Subclasses must either implement all abstract methods or also be declared abstract.
  • CANNOT have: abstract static methods or abstract constructors! Concrete methods are allowed.

Interfaces & Java 8/9 Features

Modern Java
  • Pure abstraction blueprint. Implemented using implements A, B (Multiple Inheritance).
  • Variables are implicitly public static final constants.
  • Default Methods (Java 8+): Have body, inherited, can be overridden.
  • Static Methods (Java 8+): Called via InterfaceName.method(); not inherited.
  • Private Methods (Java 9+): Helper code shared between default/static methods.
  • Default Method Clash Resolution: InterfaceName.super.methodName().
💡 1-Liner: Default methods allow interface enhancement without breaking existing classes; clashes are resolved using InterfaceName.super.method().

Nested Interfaces & Partial Impl

Slide Coding
  • Nested Interface: Declared inside a class/interface (e.g. Computer.USBDevice). Can be public, protected, private.
  • Extending: An interface can inherit another using extends (e.g. interface B extends A).
  • Partial Implementation: If a class implements an interface but omits some methods, the class must be declared abstract!

  • Subclass Manager(name, salary, department) using super(name, salary).
  • Overrides displayDetails() to display employee info + department.
  • Demonstrates accessing inherited members in subclass constructor and methods.

Slide Coding Problem
  • Abstract Employee(name, id) with abstract calculateSalary() and concrete displayDetails().
  • FullTimeEmployee: monthlySalary.

Interface Constants
  • interface SharedConstants: NO=0, YES=1, MAYBE=2, LATER=3, SOON=4, NEVER=5.
  • All variables are implicitly public static final.
  • Question and AskMe classes implement the interface to share standard decision flags.

Java Coding Conventions & Build Tools (Maven & Gradle)

Coding Conventions & Naming

Best Practices
  • Classes & Interfaces: PascalCase (e.g. StudentRecord, PaymentProcessor).
  • Methods & Variables: camelCase (e.g. calculateSalary(), totalMarks). Prefer verbs for methods.
  • Constants: UPPER_SNAKE_CASE with final (e.g. MAX_MARKS).
  • Packages: All lowercase (e.g. com.example.student).
  • Formatting: 4 spaces indentation, opening brace { on same line, spaces around operators (a + b).
  • Class Order: 1. Constants → 2. Instance Variables → 3. Constructors → 4. Methods.

Why Build Tools & Repositories

Architecture
  • Without build tools: Manual compilation, manually downloading dozens of JARs, classpath hell.
  • Automates: Compilation, dependency resolution, testing, packaging (JAR/WAR), plugin management, CI/CD.
  • Transitive Dependency: If App depends on Library A, and Library A depends on B, the build tool automatically resolves and downloads B!
  • Repositories: Remote (Maven Central) → downloaded once to Local Cache (~/.m2/repository for Maven).
💡 1-Liner: Transitive dependency management prevents developers from manually hunting down and resolving nested third-party library dependencies.

Maven: POM & Lifecycles

Maven Core
  • Philosophy: "Convention over configuration" (Standard paths: src/main/java, src/test/java, target/).
  • pom.xml (GAV Coordinates):
    • groupId: organization/package (e.g. com.example)
    • artifactId: project/module name (e.g. student-app)
    • version: project release version (e.g. 1.0).
  • Default Lifecycle: validate → compile → test → package → verify → install → deploy.
  • Running mvn package automatically runs earlier phases (compile, test) first!
  • Key Commands: mvn clean, mvn compile, mvn test, mvn package, mvn clean package.

Gradle & The Gradle Wrapper

Gradle Core
  • Uses flexible Groovy or Kotlin DSL (build.gradle or build.gradle.kts) instead of XML.
  • Task-based: Units of work like compileJava, test, jar, build.
  • Gradle Wrapper (gradlew / gradlew.bat): Bundled scripts so any developer or CI runner executes ./gradlew build without manually installing Gradle!
  • Ensures exact, consistent Gradle version across whole team.

What is a Framework & Collection?

Core Definition
🌱 Everyday Analogy: A framework is like a pre-built house frame with plumbing and electrical wires already in place — you don't rebuild the foundation, you just furnish it!
  • Framework: Ready-made architecture of classes & interfaces performing standardized tasks.
  • Java Collection: A single unit that groups multiple objects together.
  • Handles all basic data operations: Searching, Sorting, Insertion, Manipulation, Deletion.

ArrayList (Dynamic Resizable Array)

List Interface
🌱 Everyday Analogy: Like a paper notepad with numbered lines. Looking up line #5 is instant, but erasing line #2 requires you to erase and slide lines 3, 4, 5 up by hand.
  • Grows and shrinks dynamically (unlike fixed-size arrays).
  • Maintains insertion order, allows duplicates, allows null.
  • Super Fast $O(1)$ random access by index: list.get(i).
  • Slower $O(n)$ insertion/deletion in middle due to element shifting.
  • Common Methods: add(), get(), set(), remove(), size(), contains(), isEmpty(), clear(), toArray().

LinkedList (List, Queue & Stack)

High Yield
🌱 Everyday Analogy: Like a train of coaches hooked together. Adding a new train car at the front or back is instant, but finding car #40 requires walking through each car one by one.
  • Doubly linked list of nodes; implements both List and Deque.
  • Fast $O(1)$ insertion/deletion at heads/ends; slower $O(n)$ index search.
  • As a FIFO Queue (First In, First Out):
    • offer(e): add to end | peek(): view front | poll(): remove front.
  • As a LIFO Stack (Last In, First Out):
    • push(e): push onto top | pop(): pop off top.
💡 1-Liner: LinkedList implements Deque, allowing it to seamlessly act as either a FIFO Queue (offer/poll) or a LIFO Stack (push/pop).

Vector & Stack (Legacy Lists)

Thread-Safe
🌱 Everyday Analogy: Vector is like an ArrayList with a security turnstile on every method (synchronized). Stack is a stack of dinner plates (top plate comes off first).
  • Vector: Similar to ArrayList, but all methods are synchronized (thread-safe, but slower).
  • Stack: Extends Vector to provide LIFO operations: push(e), pop(), peek(), empty().
  • Modern Java replaces Stack with ArrayDeque for single-threaded speed.

PriorityQueue & ArrayDeque

Queue & Deque
🌱 Everyday Analogy: PriorityQueue is like an emergency triage room: the highest priority patient is treated first regardless of arrival time. ArrayDeque is a fast 2-way tunnel.
  • PriorityQueue: Elements ordered by natural priority (min-heap) or custom Comparator. poll() always retrieves smallest/highest-priority item.
  • ArrayDeque: Resizable array implementing Deque. Faster than Stack and LinkedList when used as stack/queue.

HashSet & Set Algebra

Unique Elements
🌱 Everyday Analogy: Like a bag of unique collectible marbles: if you drop in a marble you already own, the bag silently ignores it. No order is promised.
  • Stores unique elements only (duplicates rejected without throwing error).
  • No insertion order; allows one null; fast $O(1)$ lookup.
  • Mathematical Set Operations:
    • Union: A.addAll(B)
    • Intersection: A.retainAll(B)
    • Difference: A.removeAll(B)
    • Subset Check: A.containsAll(B)
    • Conditional Remove: set.removeIf(n -> n > 20).

SortedSet & TreeSet

Sorted Set
🌱 Everyday Analogy: Like an automated alphabetical bookshelf: any book you place in is automatically slotted into sorted alphabetical order.
  • Stores unique elements in ascending natural sorted order (or custom Comparator).
  • Implemented using a Red-Black self-balancing binary search tree.
  • $O(\log n)$ time for search, insertion, and deletion.
  • Does NOT allow null values (throws NullPointerException on comparison).

HashMap (Key-Value Storage)

Map Interface
🌱 Everyday Analogy: Like a hotel key-card rack: key #204 opens Room 204 instantly. Keys must be unique, but two different rooms can have identical TVs inside!
  • Stores key-value pairs; Keys must be unique (values can duplicate).
  • Allows one null key and multiple null values; fast $O(1)$ retrieval.
  • Key Methods: put(k, v), get(k), remove(k), containsKey(k), containsValue(v), size().
  • Advanced: putIfAbsent(k, v), getOrDefault(k, defaultVal), replace(k, newVal).
  • Traversal: keySet() for keys, entrySet() for Map.Entry<K,V>.

Iterator & Safe Deletion

Exam Trap
🌱 Everyday Analogy: Like a laser pointer guiding you through a checklist one by one. Calling it.remove() crosses off an item safely without causing you to lose your spot.
  • Used to step through collections: hasNext() and next().
  • Why use Iterator instead of for-each? Modifying a collection inside a regular for-each loop throws ConcurrentModificationException!
  • it.remove() is the only safe way to remove elements while actively iterating.
  • Works across all: Lists, Sets, and Map key sets / entry sets.
💡 1-Liner: Always use it.remove() during iteration to avoid ConcurrentModificationException caused by modifying the backing collection during loop execution.

Comparator & Custom Sorting

java.util.Comparator
🌱 Everyday Analogy: A custom referee with a rulebook: you can tell the referee to rank students by marks, rank them by age, or send all missing scores (nulls) to the very back!
  • Defines custom sorting logic for objects using lambdas: (a, b) -> a - b.
  • Built-in Factory Methods:
    • Comparator.naturalOrder() (Ascending)
    • Comparator.reverseOrder() (Descending)
    • c.reversed() (Inverts sorting)
    • Comparator.nullsFirst(...) & nullsLast(...).
  • Used with list.sort(comparator) or Collections.sort(list, comparator).

Generics & Type Safety

Type Safety
🌱 Everyday Analogy: Like a labeled medicine bottle: 'Aspirin Only'. The pharmacist stops you from accidentally putting in cough syrup before you even leave the pharmacy.
  • Without Generics (Raw Type): ArrayList list = new ArrayList(); can hold mixed types, leading to dangerous runtime ClassCastException.
  • With Generics: ArrayList<String> list = new ArrayList<>(); enforces type check at compile-time.
  • Advantages: Catches bugs at compile time; eliminates manual explicit casting; cleaner and safer code.

Core Java Utility Classes

java.util & time

Exception Handling

Exception vs Error & Hierarchy

Hierarchy
  • Root class: Throwable splits into:
    • Error: Irrecoverable system failures (e.g. OutOfMemoryError, StackOverflowError). Do not catch!
    • Exception: Abnormal conditions that applications should catch and handle.
  • Checked Exceptions: Verified at compile time (e.g. IOException, SQLException). Must handle with try-catch or declare with throws!
  • Unchecked Exceptions: Subclasses of RuntimeException (e.g. NullPointerException, ArithmeticException). Not checked at compile time.

Try-Catch-Finally & Ordering

Exam Trap
  • Catch Ordering Rule: Specific exceptions must come FIRST, superclass Exception must come LAST!
  • Placing general catch(Exception e) first causes a Compile Error: unreachable code!
  • Finally block: Guaranteed to execute whether exception occurred or not (used for cleanup like closing files/DB).
  • Multi-catch (Java 7+): Combine handlers using pipe symbol: catch (ArithmeticException | ArrayIndexOutOfBoundsException e).
💡 1-Liner: Catch clauses evaluate top-to-bottom; placing a superclass handler above a subclass handler shadows it and triggers a compiler error.

Exception Propagation

Call Stack
  • When an exception is thrown inside a method and not caught, it drops off the call stack to the caller method.
  • JVM unrolls the stack searching outwards until an appropriate enclosing catch block is found.
  • If unhandled all the way to main(), the JVM prints a stack trace and abruptly terminates the program!
💡 1-Liner: Uncaught exceptions propagate backward up the method invocation stack until an enclosing catch block intercepts them or JVM terminates.
