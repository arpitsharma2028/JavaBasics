What is a Framework / Collection?

Framework

A set of classes and interfaces that provides a ready-made architecture. A good object-oriented design includes a framework — a collection of classes where every class performs the same kind of task.

Java Collection

A single unit made up of multiple objects (a group). The Collections Framework provides interfaces — List, Set, Queue, Deque — and classes — ArrayList, Vector, LinkedList, PriorityQueue, HashSet, LinkedHashSet, TreeSet — to implement data structures and algorithms: searching, sorting, insertion, manipulation, and deletion.

Hierarchy of the Collection Framework

Note: Map (and HashMap, covered below) is part of the Collections Framework but does not extend the Collection interface — it stores key/value pairs instead of single elements, so it sits outside this tree as its own root. Vector, Stack, PriorityQueue, Deque/ArrayDeque, LinkedHashSet, SortedSet and TreeSet appear in this hierarchy diagram; this deck's worked examples and method lists focus on ArrayList, LinkedList and HashSet (with LinkedList also demonstrated acting as a Queue and a Stack).
Interface

List

Stores an ordered collection of objects. Duplicate values are allowed.

Implemented by

  • ArrayList
  • LinkedList
  • Vector
  • Stack

Syntax

List<data-type> list1 = new ArrayList();
List<data-type> list2 = new LinkedList();
List<data-type> list3 = new Vector();
List<data-type> list4 = new Stack();

The List interface defines methods to insert, delete, and access elements — implemented below by ArrayList and LinkedList.

Class

ArrayList

Package: java.util.ArrayList  ·  Import: import java.util.ArrayList;

What it is

A resizable (dynamic) array that stores a group of objects in insertion order and allows duplicate values — unlike a normal array (String[] students = new String[3]), whose size is fixed once created.

ArrayList<String> students = new ArrayList<>();

Characteristics

  • Dynamic size
  • Maintains insertion order
  • Allows duplicate elements
  • Fast random access
  • Allows null values
  • Slower insertion/deletion in the middle

Class

LinkedList

Package: java.util.LinkedList  ·  Implements List and Deque using a doubly linked list internally

What it is

Stores elements as nodes connected through links, rather than a contiguous array. Can be used as a List, Queue, or Deque.

Characteristics

  • Part of Java Collection Framework
  • Dynamic memory allocation
  • Dynamic size — grows/shrinks automatically
  • Maintains insertion order
  • Allows duplicate elements
  • Allows null values
  • Index-based access supported
  • Fast insertion/deletion at beginning or end
  • Slower random access than ArrayList

Example — LinkedList as a Queue

import java.util.LinkedList;
public class Main {
  public static void main(String[] args) {
    LinkedList<String> queue = new LinkedList<>();
    queue.offer("A"); queue.offer("B"); queue.offer("C");
    System.out.println("Front: " + queue.peek());
    System.out.println("Removed: " + queue.poll());
  }
}

import java.util.HashMap;
import java.util.Map;
public class Main {
    public static void main(String[] args) {
        HashMap<Integer, String> students = new HashMap<>();
        students.put(101, "Rahul");
        students.put(102, "Priya");

        }
    }
}

Iterator

Package: java.util.Iterator

What it is

Used to traverse (visit) the elements of a collection one by one.

Methods & Syntax

MethodSyntaxPurpose
hasNext()it.hasNext()Checks if another element exists
next()it.next()Returns the next element
remove()it.remove()Removes the current element

Works across every collection type

  • ArrayList → list.iterator()
  • HashSet → set.iterator()
  • LinkedList → list.iterator()
  • HashMap keys → map.keySet().iterator()
  • HashMap values → map.values().iterator()

Example — remove a specific element while iterating

import java.util.ArrayList;
import java.util.Iterator;
public class Main {
  public static void main(String[] args) {
    ArrayList<String> students = new ArrayList<>();
    students.add("Rahul"); students.add("Priya"); students.add("Aman");
    Iterator<String> it = students.iterator();
    while (it.hasNext()) {
      String name = it.next();
      if (name.equals("Priya")) it.remove();
    }
    System.out.println(students);
  }
}

Generics

What it is

Generics let you specify what type of data a collection can store: ArrayList<Integer> numbers = new ArrayList<>(); — here <Integer> means the ArrayList can store only Integer values.

Without Generics — mixed types allowed, causes problems

ArrayList list = new ArrayList();
list.add(10);
list.add("Hello");
list.add(20.5); // mixed types → problems when retrieving

With Generics — only the declared type is allowed

ArrayList<Integer> list = new ArrayList<>();
list.add(10); list.add(20); list.add(30);
list.add("Hello"); // ✗ compile-time error

Main advantages

  • Type safety — only the specified type can be stored
  • No need for explicit casting when retrieving objects
  • Errors are detected at compile time
  • Makes programs easier to read and maintain

Generics across the framework

ArrayList<String> names = new ArrayList<>();
HashSet<String> cities = new HashSet<>();
HashMap<Integer, String> students = new HashMap<>();

Type Safety

What it is

The compiler checks that only the correct type of objects can be stored in a collection, preventing many runtime errors — achieved with Generics (<>).

Without Type Safety — runtime error

ArrayList list = new ArrayList();
list.add("Rahul");
list.add(100);
String name = (String) list.get(1); // ClassCastException at runtime

With Type Safety — no casting needed

ArrayList<String> students = new ArrayList<>();
students.add("Rahul"); students.add("Priya");
String name = students.get(0); // safe, no cast required

In the Collection Framework

  • Ensures a collection contains only the specified data type
  • Achieved using Generics (<>)
  • Provides compile-time type checking
  • Reduces the possibility of runtime errors
  • Eliminates unnecessary type casting
  • Makes programs safer and easier to understand

Advantages of the Collections Framework

  • Dynamic data storage
  • Efficient searching and sorting
  • Built-in algorithms
  • Reduces coding effort
  • Supports Generics for type safety
  • Improves code reusability and maintainability
